## What's New in v2.0.7

### 🎯 Unified item detail flow

The detail view (desktop window + mobile overlay) now derives its actions from the Xbox connection state and the installed badges — no more manual modes:

- **Not connected** → inline "Not connected" notice with a **Connect** button; connecting refreshes the detail in place
- **Not installed** → **Install**
- **Installed, up to date** → "Installed" status + **Reinstall** / **Uninstall**
- **Installed, outdated** → green "Update available" chip + **Update** / **Uninstall** (chip is now green, was red)

Manual "Check Installed"/"Re-check" buttons are gone — install state is always resolved from what the connected Xbox reports.

### 🔌 Connecting actually connects

- `ConnectionViewModel.ConnectAsync` tested the connection but never marked the app as connected — every connect path (sidebar, detail, mobile) left the app "not connected" and a still-open detail window stayed stale. Connect now flips the state and the open detail updates its buttons and badges instantly
- Detail **Update/Install** buttons stayed disabled after connecting — enablement is now re-derived when the connection state changes

### 📦 Install & Detail Fixes

- **Reinstall/Uninstall from the browse detail** — previously did nothing when the detail opened from Browse; now resolves the installed package from the resolved match
- **Uninstall feedback** — the detail-view uninstall now runs a full flow: confirm dialog → "Uninstalling…" spinner overlay → badge refresh → close on success or inline error on failure
- **Post-install false FAILED fixed** — the package list could report stale data right after the package manager settled, wrongly reporting installs as failed. A genuine settle (accepted upload + package manager Ready) is now trusted as success, with package-list verification only for premature settles
- **Uninstall confirm no longer crashes** — the confirm dialog referenced a nonexistent icon asset; it now uses the correct one (desktop + mobile)

### ⌨️ Android wizard keyboard awareness

The setup/custom-install wizards now react when the on-screen keyboard opens: the hero collapses to a one-line title bar, the title bar shrinks, the breadcrumb compacts to a "Step n of m" summary, scroll room is reserved for the keyboard, and the focused field is brought back into view — so more form fields fit and stay reachable while typing. Built on Avalonia's cross-platform InputPane API (no per-platform insets code).
