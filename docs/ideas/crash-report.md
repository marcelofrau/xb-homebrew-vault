# Automatic Crash Report

**Impact:** High | **Effort:** Low | **Suggested priority:** Phase 1

## Problem

When the app crashes, users don't report it — they just close it. Critical bugs go unfixed for months because the developer never finds out.

## Security constraint

GitHub Issues API requires a token. Storing a token in a public app is not viable — anyone can extract it from the assembly.

**Solution:** Prefilled GitHub Issues URL (no token required).

```
https://github.com/marcelofrau/xb-homebrew-vault/issues/new?title=<encoded>&body=<encoded>
```

`Process.Start()` with `UseShellExecute=true` opens in the default browser. User reviews and clicks "Submit Issue".

## Proposal

### 1. Manual trigger

- **ErrorDialog** — "Report Issue" button alongside Copy Error / Restart
- **Help > Report Bug menu** — available at any time (not just on crash)

### 2. Collected data

| Field | Source | Example |
|-------|--------|---------|
| Version | `BuildInfo.DisplayVersion` | v1.0.1 |
| Platform | `RuntimeInformation.OSDescription` | Windows 10.0.22631 |
| Architecture | `RuntimeInformation.ProcessArchitecture` | X64 |
| Exception | `Exception.ToString()` | System.NullReferenceException: ... |
| Log | Last 50 lines of log file | `[2026-07-04 15:30:00] ERROR ...` |
| Config | `settings.json` (without credentials) | MinLogLevel: Info |
| Action | User context (optional, textarea) | "Happened when I clicked Install" |

### 3. Issue format

**Title:** `[Crash] v1.0.1 — NullReferenceException em BrowseView`

**Body:**
```
**Version:** v1.0.1
**Platform:** Windows 10.0.22631 (X64)
**Exception:**
```
System.NullReferenceException: Object reference not set to an instance of an object.
   at XBVault.ViewModels.BrowseViewModel.LoadCatalog() in BrowseViewModel.cs:123
```

**Last 50 log lines:**
```
[2026-07-04 15:30:00] INFO: Application starting
[2026-07-04 15:30:05] ERROR: Failed to load catalog
```

**Settings (without credentials):**
```json
{"MinLogLevel":"Info","CheckForUpdatesOnStartup":true}
```

---
*Crash report automatically generated by XB Homebrew Vault.*
```

### 4. Sanitization

Before building the URL, strip:
- Xbox connection credentials (IP address, user, password)
- Tokens or secrets in config files
- Absolute local user paths (optional)

### 5. Implementation

```csharp
static class CrashReportBuilder
{
    static string BuildUrl(Exception ex)
    {
        var title = Uri.EscapeDataString($"[Crash] {BuildInfo.DisplayVersion} — {ex.GetType().Name}");
        var body = Uri.EscapeDataString(BuildBody(ex));
        return $"https://github.com/marcelofrau/xb-homebrew-vault/issues/new?title={title}&body={body}";
    }

    static void OpenInBrowser(string url)
    {
        Process.Start(new ProcessStartInfo
        {
            FileName = url,
            UseShellExecute = true
        });
    }
}
```

### 6. UX

- Button in ErrorDialog: "Report Issue" (bug icon, Classes="Accent")
- On click: browser opens with prefilled issue
- Toast notification: "Issue prefilled — review and submit in your browser"
- Help > Report Bug menu: same flow, but without exception (just version + logs + "optional description")

## Limitations

- GitHub Issues URL has a length limit (~8KB for the full URL). Very long logs may be truncated.
- Cannot attach files (screenshots, dumps). User needs to attach manually in browser.
- Requires internet connection.
- User needs a GitHub account to submit.
